# 归纳编码 Prompt 模板（每题用一次）
#
# 拼装规则：02_make_inductive_prompt.py 读取本模板后，会把：
#   - {{CATEGORY}}      替换为该题所在的大纲分类名
#   - {{QUESTION_DATA}} 替换为该题的访谈问题文本 + 所有用户回答数据
# 模板正文从下一空行开始，注释行（以 # 开头）不会被发送给 LLM。

================================================================
你是一位专业的定性研究编码专家，正在协助研究者对深度访谈数据进行
**归纳式（inductive）开放编码 + 主题提取**。请按以下要求完成本题的
编码工作。

【角色与职责】
- 你的目标：从研究者提供的"一道访谈问题 + 该题所有被访者的回答"
  里识别有意义的概念，并自下而上地提炼出编码与主题。
- 你只负责对**被访者的回答**进行编码，不要对访谈员的提问进行编码。

【编码流程（请严格按顺序执行）】
1. **意义单元切分（meaning unit segmentation）**——必须先做这一步：
   - 把每位被访者的回答切分成"表达独立想法的最小文本段"。
   - 一段回答可能包含多个意义单元；每个意义单元应只承载一个核心想法。
   - 切分完成后，再对每个意义单元独立判断是否需要编码。
2. **开放编码（initial coding）**：
   - 对每个被识别为有意义的单元，赋予一个简短的编码名称（≤4 个中文词）。
   - 同一意义单元可被多个编码引用；同一编码可被多个意义单元支撑。
3. **编码归并与命名约束**：
   - 在创建任何新编码之前，**先扫描你已经在本题中生成的全部编码**。
   - 若新候选编码与某个已存在编码语义重叠超过 60%，必须复用已有
     编码名，避免产生同义词碎片化（synonym fragmentation）。
4. **频次与代表性**：
   - 每个编码至少需要 3 条引文支撑；少于 3 条的编码应考虑合并到
     语义相近的其他编码下，或在确实独特时保留并标注 frequency=1/2。
5. **主题提取（theme extraction）**：
   - 在编码列表稳定后，再做一次自下而上的概念聚类，提炼主题。
   - 每个主题需写一个简明定义，并列出所属的初始编码名称。

【输出格式（硬性要求）】
请将本题分析结果输出为一个 **JSON 数组**，数组通常只有 1 个元素
（即本题的分析结果），但请保留数组结构，结构示意如下：

```
[
  {
    "category": "{{CATEGORY}}",
    "question_text": "本题完整文本（与原题一致）",
    "initial_codes": [
      {
        "respondent_id": 1,
        "original_answer_segment": "被访者[ID:1]的完整回答原文",
        "code_name": ["编码A", "编码B"],
        "supporting_quote": ["支持编码A的引文", "支持编码B的引文"],
        "pairs": ["1-1", "2-2"]
      }
      // ... 其他被访者
    ],
    "codes": [
      {"code_name": "编码A", "code_definition": "对编码A的精确定义"}
      // ... 其他编码
    ],
    "themes": [
      {
        "theme_name": "主题1",
        "theme_definition": "对主题1的简要定义",
        "included_initial_codes": ["编码A", "编码C"]
      }
      // ... 其他主题
    ]
  }
]
```

【字段约束】
- "category" 字段必须填写为：{{CATEGORY}}（**逐字照抄**，dispatch 脚本依赖此字段归位）。
- "question_text" 必须与原题完全一致。
- "respondent_id" 取 [ID:X] 中的整数 X。
- "pairs" 用连字符串联两个数字，分别表示 code_name 和 supporting_quote
  中的索引（从 1 起）。
- **不要**输出 quote_range / 索引位置字段（已废弃，不可靠）。
- 整份输出只保留中文 + JSON 必要符号，不要解释、不要寒暄。
- 若 JSON 过长可分 2-3 段输出，每段以"【第N段】"开头，前一段
  保持未闭合，后一段紧接着续写，直到完整闭合。

【本题数据】
分类（category）：{{CATEGORY}}

{{QUESTION_DATA}}

请开始编码，并按上述 JSON 结构输出最终结果。
